# Демо-видео по интерфейсу проекта

Инструмент лежит в `tools/demo-video/`. Один прогон делает готовый mp4 с русской озвучкой:

```bash
make demo-video
```

Результат — `storage/app/demo-video/operator-flow.mp4`. Playwright и ffmpeg живут в разовом контейнере
`mcr.microsoft.com/playwright`, зависимости приложения не трогаются.

## Устройство конвейера

Три шага, строго в этом порядке:

1. `tts.mjs` — озвучивает текст всех сцен через OpenAI TTS и складывает длительности в `timings.json`.
   Кэш по хэшу текста: правка одной реплики переозвучивает только её.
2. `record.mjs` — прогоняет сценарий с записью экрана. Сцена держится **не меньше**, чем звучит её
   реплика; фактическая длительность каждой сцены пишется в `scene-durations.json`.
3. `build.mjs` — добивает каждую реплику тишиной до **фактической** длины её сцены, склеивает дорожку
   и мультиплексирует с видео.

Ключевое свойство: озвучка генерируется до записи, поэтому длительность реплики известна заранее, а
сборка выравнивается по факту — расхождение голоса с картинкой не накапливается от сцены к сцене.
Не пытайся синхронизировать вручную подбором пауз; если реплика длиннее действий, сцена просто
подождёт.

## Сцена

Сценарий — массив сцен в `tools/demo-video/scenario.mjs`. Сцена это текст закадрового голоса плюс
действия:

```js
{
    id: 'listing-list',
    narration: 'Список объявлений открывается на вкладке «Все» — и это важно…',
    async run(page) {
        await page.goto(`${BASE_URL}/admin/marketplace/listings`);
        await settle(page, 1200);
        await highlight(page, page.locator('.fi-tabs').first(), { ms: 2200 });
        await hover(page, tab(page, 'На модерации'), { linger: 1200 });
    }
}
```

`id` попадает в имена файлов озвучки и в лог прогона — держи его коротким и латиницей.

Инструмент рассчитан на **один** сценарий: `tts.mjs` и `record.mjs` импортируют `./scenario.mjs`
напрямую. Это осознанное ограничение, а не забытый TODO. Для второго ролика заведи файл рядом
(`scenario-<name>.mjs`) и переключи импорт в обоих скриптах, либо сначала обобщи инструмент — но не
делай второе по своей инициативе, если просили только ролик.

## Хелперы `actions.mjs`

Клики идут через `page.mouse`, а не `locator.click()`: иначе в записи не видно движения.

| Хелпер | Назначение |
| --- | --- |
| `click(page, locator, { settle })` | подвести курсор и нажать |
| `hover(page, locator, { linger })` | подвести и задержаться — «смотрите сюда» |
| `type(page, locator, text, { delay, clear })` | набор посимвольно |
| `highlight(page, locator, { ms })` | оранжевая рамка на время |
| `settle(page, ms)` | дождаться, пока Livewire перестанет перерисовывать |
| `field(scope, name)` | поле по имени состояния |
| `select(page, scope, name, option, { search })` | выбор в селекте, нативном или searchable |
| `button(scope, label)` | действие по подписи |
| `tab(scope, label)` | вкладка списка |

`scope` — `page` или локатор модального окна (`page.locator('.fi-modal-window').last()`).

## Разметка Filament 5

Каждый пункт ниже стоил упавшего прогона. Проверено на живых страницах этого проекта.

**Поля адресуются по хвосту id, а не по подписи.** На странице ресурса id выглядит как `form.title`,
внутри модального окна действия — `mountedActionSchema0.phone`, поэтому `field()` ищет по
`[id$=".title"]`. По подписи искать нельзя: слово «тип» встречается и в тексте подсказки готовности к
публикации, и фильтр по тексту цепляет чужой блок.

**Обёртка поля — `.fi-fo-field`** (не `.fi-fo-field-wrp`, такого класса в v5 нет).

**У searchable-селекта элемента с id нет вовсе** — есть только `label[for$=".location_id"]`,
ссылающаяся в пустоту. Блок такого поля ищется по этой подписи.

**Выпадающий список селекта:** кнопка `.fi-select-input-btn`, поиск
`.fi-select-input-search-ctn input:visible`, пункт `.fi-select-input-option:visible`. Фильтр по
видимости обязателен: у каждого закрытого селекта на странице есть собственный скрытый поиск, и
`.first()` без `:visible` попадёт не в тот.

**Иконочные кнопки опознаются по `aria-label`:** «+» рядом с селектом — `button[aria-label="Create"]`,
фильтр таблицы — `button[aria-label="Filter"]`.

**Действия рендерятся то `<button>`, то `<a>`** — «Новое объявление» ссылка, «Опубликовать» кнопка.
Ищи оба тега; `getByRole('button')` половину действий не найдёт.

**Вкладки списка** — кнопки внутри `.fi-tabs`. **Строки таблицы кликабельны**: ячейки это ссылки
`a.fi-ta-col`, ведущие на страницу редактирования.

Интерфейс Filament остаётся англоязычным (`APP_LOCALE=en`): «Sign in», «Create», «Cancel», «Filter».
Русские только подписи полей и действий, заданные в коде ресурсов.

## Грабли окружения

**Chromium апгрейдит `http://` до `https://`** для любого хоста, кроме `localhost`. Обращение к
приложению по имени сервиса `app:8000` внутри compose-сети падает на `ERR_SSL_PROTOCOL_ERROR`, хотя
curl тот же адрес открывает. Поэтому контейнер запускается с сетью хоста и ходит на
`http://localhost:8800`. Не «чини» это отключением фич Chromium — не помогает.

**Контейнер работает root-ом** (ffmpeg ставится apt-ом), поэтому в конце прогона результат отдаётся
владельцу проекта. Без этого видео не перезаписать и не удалить без sudo.

**Запись Playwright не содержит курсора.** Указатель, «пульс» клика и подсветку рисует
`cursor-overlay.js`, поставленный через `addInitScript` и переживающий Livewire-перерисовки. Без него
зритель видит, как поля заполняются сами собой.

## Побочные эффекты

Демо пишет в ту же базу, что и разработка: за прогон появляется контакт-поставщик (номер уникален) и
объявление.

**Действия, отправляющие сообщение в WhatsApp, в демо не подтверждаются.** «Одобрить» и «Отклонить»
шлют поставщику настоящее сообщение — сцена показывает очередь, кнопки и окно с причиной отклонения,
после чего окно закрывается. Публикация в демо идёт действием «Опубликовать»: оно не отправляет
уведомлений по определению, потому что объявление, набранное оператором, согласовано с поставщиком по
телефону. Добавляя сцену, проверяй по коду ресурса, не шлёт ли действие уведомление.

## Отладка

При падении сцены сохраняется скриншот `storage/app/demo-video/video/failed-<scene>.png`, а прогон
останавливается — незаконченное видео не собирается.

Селекторы снимай живьём браузерными MCP-инструментами на `http://localhost:8800`, а не угадывай:
один упавший прогон стоит нескольких минут, а осмотр страницы — секунды. Полезный приём — выполнить в
странице JS и вернуть список подписей, id и классов интересующего блока.

Требования к прогону: поднятый стек (`make up`), `OPENAI_API_KEY` в `.env`, справочники и хотя бы одно
объявление в статусе «На модерации» — иначе сцена про очередь модерации не найдёт строку.

Учётка для входа — `demo-operator@example.com`, `run.sh` создаёт её идемпотентно и чужих аккаунтов не
трогает.

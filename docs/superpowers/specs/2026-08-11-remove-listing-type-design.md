# Убрать тип объявления: сервис только про спецтехнику

**Дата:** 2026-08-11
**Статус:** согласовано

## Задача

Убрать из категорий поле «тип» и перестать спрашивать тип везде, где он спрашивается. Категории — только спецтехника. Услуги как вид объявления откладываются и позже будут переделаны, поэтому текущая модель сохраняться не должна.

## Решение

Понятие «тип объявления» (`Техника` / `Услуга`) удаляется целиком: из базы, из справочника категорий, из объявлений, из диалога бота, из веб-формы поставщика, из админки, из каталога и из документации.

На момент решения в базе нет ни одной строки с типом `service`: 73 категории и 37 объявлений — все `equipment`. Бэкфилл и миграция данных не нужны.

## Что меняется для пользователя

- Тип не спрашивается нигде: ни ботом, ни веб-формой, ни админкой.
- Тип не показывается в карточках каталога, на странице объявления и в «Моих объявлениях».
- Категория ничего не «типизирует» — это просто категория. Список категорий больше ни от чего не зависит.
- Марка становится безусловной: правило «марка есть только у техники» исчезает вместе с услугами.
- Обязательных бизнес-полей для публикации становится пять: название, категория, описание, локация, цена.
- В боте «Я поставщик» ведёт сразу к AI-сборщику, без промежуточного вопроса «Что вы предлагаете?».
- Тексты, называющие сервис «арендой спецтехники и услуг», говорят про спецтехнику.

## Решения и их обоснование

**Колонки удаляются, а не остаются с дефолтом.** Услуги вернутся «немного переделанными», то есть в другой модели; сохранённое поле было бы мёртвым и требовало бы дисциплины при каждой записи. Вместе с колонками уходит целый класс инвариантов — «тип объявления обязан совпадать с типом его категории» — который сегодня продублирован в четырёх местах (AI, админка, веб-форма, доки). `down()` миграции возвращает обе колонки с дефолтом `equipment`, поэтому откат не теряет строки.

**Типовой сценарий переустанавливается, а не правится миграцией.** Живой граф в базе совпадает с типовым, а `bot:install-default-scenario --force` — штатный механизм проекта. Точечная миграция JSON-определений была бы аккуратнее к кастомизированным графам, но здесь кастомизации нет, а сложность правки графа (вырезать узел, схлопнуть две ноды, перекинуть связи, и то же самое во всех сохранённых версиях) не оправдана.

**Демо-ролик не перезаписывается.** Playwright-сценарий чинится, чтобы `make demo-video` проходил, но пересборка ролика тратит вызов OpenAI TTS и полный прогон записи — это отдельное действие владельца ключа.

**Векторы семантического поиска не пересчитываются массово.** Удаление строки `Тип: Техника` из текста эмбеддинга меняет отпечаток у всех объявлений, и каждое переэмбедится при следующем сохранении. Строка была одинаковой у всех объявлений и ничего не различала, поэтому старые векторы остаются пригодными до тех пор.

## Границы

- Услуги не заменяются ничем: отдельного признака, флага или категории-заглушки не появляется.
- Каталог заказчика фильтра по типу не имел и не приобретает замены.
- Исторические документы `docs/superpowers/**` не переписываются.
- Локальная копия ТЗ разойдётся с оригиналом в Google Docs — синхронизация оригинала за владельцем документа.

## Эффекты, о которых нужно знать при выкатке

- После деплоя требуется `bot:install-default-scenario --force`. Флаг перезаписывает все три типовых сценария, а не только главный.
- Отпечаток AI-узла меняется, поэтому активные сессии на шаге сбора объявления получают мягкий сброс в главное меню.
- Мета-строка карточки перестаёт быть гарантированно непустой (тип всегда давал хотя бы один сегмент) — она скрывается, когда нет ни категории, ни марки.

## Риски реализации

- `tests/Pest.php::categoryNamed()` держит тип в сигнатуре, и против неё компилируются десятки вызовов: этот хелпер правится первым, иначе не запускается ни один тест.
- `UpdateSupplierListingRequest` связывает категорию с типом через `Rule::exists(...)->where('type', $this->input('type'))`. Если убрать поле, оставив правило, оно превратится в `where('type', '')` и отклонит любую категорию. Поле и правило уходят вместе.
- `new ListingExtractionAgent(null, ...)` вызывается с позиционным `null` под удаляемый параметр — при простом удалении параметра массив категорий молча съедет в чужой слот.
- `$listing->type->getLabel()` вызывается без защиты в четырёх blade-шаблонах: удаление колонки без правки шаблонов даёт фатальную ошибку.
- Инлайновый JS формы поставщика разыменовывает `document.getElementById('type').value` — уходит вместе с полем.
- `tools/demo-video/scenario.mjs` кликает по селекту «Тип»: без правки `make demo-video` падает по таймауту, а не с внятной ошибкой.
- `CategorySeederTest` доказывает, что сидер не перетирает операторские категории, используя тип как единственную метку — ему нужен другой признак, иначе тест перестанет что-либо проверять.
